# 放大宝石矿 YOLO 模型训练与二次确认接入设计

## 目标

使用 `C:\Users\54459\Desktop\bigGem` 中已标注的放大宝石矿图集训练独立的 YOLOv8n 单类别检测模型 `bigGem.onnx`，并将其接入所有通过 `verifyGemAtCenter()` 执行的宝石二次确认路径。

新模型仅用于放大后的宝石确认，不替换、不覆盖现有全图检测模型 `gem.onnx`。普通采集、专注采集和分享矿采集统一使用新模型完成二次确认。

## 当前数据与环境

图集包含：

- 160 张图片；
- 160 个同名 YOLO 标签文件；
- 每张图片包含 1 个类别 `0` 的标注框；
- 图片尺寸为 `1600×900` 或 `1599×899`；
- 所有标签均为合法的 YOLO 归一化坐标；
- 无空标签、缺失配对或格式错误。

本机训练环境：

- Python 3.10；
- Ultralytics 8.4.61；
- PyTorch CPU 版本；
- 无可用 CUDA GPU。

现有 `gem.onnx` 是 `gem / tieshou / hero` 三类别模型，本次不对其进行修改。

## 训练方案

采用 Ultralytics YOLOv8n 迁移学习：

- 初始权重：`yolov8n.pt`；
- 任务类型：目标检测；
- 输入尺寸：`640×640`；
- 类别数：1；
- 使用早停；
- 生产候选权重使用指标最优的 `best.pt`，不使用最后一轮 `last.pt`。

训练分两个阶段：

1. 短轮次试训，确认数据读取、标签解析、训练、验证和 ONNX 导出链路正确；
2. 正式训练，依靠早停结束并保存最佳权重。

由于当前环境只有 CPU，训练耗时可能较长，但不改变模型架构或验收标准。训练输出应保留：

- `best.pt`；
- Precision、Recall、mAP50、mAP50-95；
- 指标曲线；
- 混淆矩阵；
- 验证集预测效果图；
- 导出的 `bigGem.onnx`。

## 模型验收与发布门槛

固定的 32 张验证集作为模型验收集。

硬性门槛：

- 验证集 Recall ≥ 0.95。

同时记录但暂不设置硬门槛：

- Precision；
- mAP50；
- mAP50-95。

人工检查验证集预测图，重点确认：

- 检测框覆盖完整宝石主体；
- 检测框中心适合作为实际点击位置；
- 周边 UI、文字、队伍状态不会被明显误识别为宝石。

通过 PyTorch 权重验收后导出固定输入尺寸 `640×640` 的 ONNX 模型，并对同一验证集执行 ONNX 推理复验。ONNX 结果的 Recall 也必须达到 0.95，防止导出前后结果发生不可接受的偏差。

只有上述门槛全部满足时，才将模型复制为：

```text
plugins/rok/models/bigGem.onnx
```

未达到门槛时不得替换生产候选文件，应调整训练轮次、超参数或补充数据后重新训练。

## 运行时架构

运行时保留两个职责独立的检测器：

- `gemDetector`：继续加载现有 `gem.onnx`，负责全图宝石搜索及其既有用途；
- `bigGemDetector`：加载新增 `bigGem.onnx`，只负责放大后的宝石二次确认。

`PluginService` 在启动时分别加载两个模型，并将两个检测器独立注入 `PluginContext`。二者不得共用可被后一次加载覆盖的字段。

`verifyGemAtCenter()` 的二次确认流程改为：

1. 截取当前既有二次确认区域；
2. 调用 `bigGemDetector` 执行检测；
3. 仅保留 `classIndex === 0` 的 `big_gem` 检测；
4. 选择置信度最高的检测框；
5. 将裁剪图中的检测中心换算为全屏坐标；
6. 返回该实际中心坐标，供后续点击使用。

普通采集、专注采集和分享矿采集均通过公共的 `verifyGemAtCenter()` 获得该行为，不在各条业务路径重复实现检测逻辑。

## 失败处理

`bigGemDetector` 没有检测到目标时，沿用现有二次确认失败流程。

明确禁止以下回退行为：

- 不再调用 `gemDetector` 进行二次确认；
- 不使用固定坐标假装确认成功；
- 不因模型不可用而跳过二次确认。

若 `bigGem.onnx` 缺失或加载失败：

- 服务输出明确的模型加载错误日志；
- `bigGemDetector` 保持不可用状态；
- `verifyGemAtCenter()` 返回未找到；
- 不影响 `gemDetector` 的独立加载和全图检测功能。

## 测试策略

### 数据准备测试

验证：

- 160 个样本全部配对；
- 固定种子产生 128/32 的稳定划分；
- 训练集与验证集无文件交集；
- 所有标签类别为 0；
- 所有坐标在 YOLO 合法范围内；
- 重复运行不会引入陈旧样本。

### 运行时单元测试

验证：

- `gem.onnx` 与 `bigGem.onnx` 被加载为两个独立检测器；
- 任一模型加载失败不会覆盖或破坏另一检测器；
- `verifyGemAtCenter()` 调用的是 `bigGemDetector`；
- 只接受 class 0，并选择最高置信度结果；
- 局部检测中心能正确换算为全屏坐标；
- 空检测结果和模型不可用时返回失败；
- 二次确认不会回退到 `gemDetector`；
- 三种采集路径继续通过公共函数获得一致行为。

### 集成验证

- 运行相关 Jest 测试；
- 运行 `npx tsc --noEmit`；
- 对固定验证集执行 `best.pt` 验证；
- 对固定验证集执行导出后的 `bigGem.onnx` 推理复验；
- 保存指标与预测效果图，作为模型发布依据。

## 非目标

本次不包含：

- 修改或重新训练现有 `gem.onnx`；
- 将 `big_gem` 合并进现有三类别模型；
- 为二次确认保留旧模型兜底；
- 改变宝石搜索、滑动、队伍分配或分享矿坐标池逻辑；
- 引入 YOLO11 或其他新模型架构；
- 在指标未达标时强制接入模型。
