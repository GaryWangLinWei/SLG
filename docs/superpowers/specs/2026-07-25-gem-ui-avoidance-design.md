# 宝石 UI 遮挡一次避让设计

**日期：** 2026-07-25

## 目标

统一普通宝石搜索中初始检测和螺旋搜索检测的候选选择与 UI 避让行为：同屏存在可点击宝石时优先处理非 UI 遮挡区候选；只有全部候选都处于 UI 遮挡区时，才执行一次避让滑动，并在等待 0.8 秒后原地重新检测一次。

## 范围

仅调整 `plugins/rok/actions/gatherGem.ts` 中 `searchAndClickGem()` 使用的普通宝石候选检测流程及其单元测试。不改变 UI 区域坐标、螺旋方向、搜索次数、占用检测、中心验证、分享矿流程或派兵流程。

## 候选选择规则

每次获得一组普通宝石检测结果后：

1. 按检测结果原有顺序寻找第一个不在 UI 遮挡区的候选。
2. 如果找到，直接将其交给现有占用检测及后续点击流程，不执行 UI 避让。
3. 如果检测结果为空，保持当前搜索阶段原有的未命中行为。
4. 如果检测结果非空但所有候选都在 UI 遮挡区，选取第一个候选执行一次 UI 避让。

这确保同屏有两个或更多候选时，不会因为第一个候选被 UI 遮挡而忽略后续可点击候选。

## 一次避让与原地重检

UI 避让继续使用现有动作：从 UI 区候选与屏幕中心 `(800, 450)` 的中点滑向屏幕中心，持续 500ms，然后等待 0.8 秒。

等待结束后立即原地调用一次 `detectWithScreenshot(0.35)`，并再次按上述规则寻找第一个非 UI 区候选。

这次重检不允许再次触发 UI 避让：

- 找到非 UI 区候选：进入现有占用检测和点击流程。
- 没有候选或所有候选仍在 UI 区：视为本次检测未找到可点击候选，恢复当前搜索阶段的正常流程。

因此，每个初始检测或螺旋检测机会最多额外产生一次避让滑动和一次原地重检。

## 初始检测行为

初始检测使用统一流程：

- 若首次检测或一次重检得到非 UI 候选，处理该候选。
- 若一次避让重检后仍无可点击候选，结束初始检测阶段并进入正常螺旋搜索。
- 不再通过重置 `checkedCenter=false` 无限重复初始 UI 避让。
- UI 避让及重检不增加 `moveCount`。

## 螺旋检测行为

每次正常螺旋滑动后的检测使用相同流程：

- 优先处理同屏非 UI 候选。
- 全部候选被遮挡时执行一次避让，并等待 0.8 秒后原地重检。
- 重检得到非 UI 候选时立即处理，不先进行下一次螺旋滑动。
- 重检仍无可点击候选时才进入下一螺旋步。
- 原有正常螺旋滑动已产生的 `moveCount` 保持不变；额外避让和重检不增加计数。

## 代码结构

抽取一个小型内部辅助流程，负责：

- 从检测结果选择首个非 UI 候选；
- 判断是否属于“所有候选均在 UI 区”；
- 必要时执行一次避让和原地重检；
- 返回最终可处理的非 UI 候选，或返回未找到。

初始检测和螺旋检测都调用该流程，避免两处分支继续产生行为差异。辅助流程不处理占用状态、点击、中心验证或螺旋状态，只负责候选选择和一次 UI 避让。

## 取消与错误处理

滑动、等待和截图检测继续通过 `PluginContext` 的可取消封装执行，因此沿用现有任务停止行为。检测或设备操作异常继续向上抛出，由现有任务执行层处理，不在辅助流程中吞掉异常。

## 测试

新增或恢复针对 `gatherGem` 的聚焦单元测试，至少覆盖：

1. 同屏第一候选在 UI 区、后续候选不在 UI 区：选择非 UI 候选且不执行避让。
2. 所有候选在 UI 区：只执行一次避让，并在 0.8 秒后原地重检。
3. 重检出现非 UI 候选：立即进入该候选的现有处理流程。
4. 重检仍全部位于 UI 区：不再次避让，恢复正常搜索。
5. 首次检测为空：不避让。
6. 额外避让和重检不增加螺旋 `moveCount`。
7. 初始检测与螺旋检测遵循同一候选选择规则。
